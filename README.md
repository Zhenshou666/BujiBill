# 不记账本 · BujiBill

微信 / 支付宝 / 校园一卡通 三源账单整合与消费分析。
可以用浏览器跑，也能打包成 Windows 桌面程序（`.exe`）。账单数据全部留在本机、不上传任何服务器。

> 课程项目：Python 程序设计

---

## 一句话说清它解决什么问题

你在微信给校园卡充了 100 元，然后刷卡吃饭花了 44 元。
**真实消费只有 44 元，但三家账单直接相加会得到 144 元。**

这个工具把「充值」识别成账户内部转账并剔除，只保留真正产生消费的那一侧记录。
示例数据（136 笔，全部为伪造）里，不做剔除会算成 **¥8,374.81**，实际只有 **¥6,849.31**，
虚增 **¥1,525.50**。这两个数由 `tools/smoke.py` 每次运行实测得出，不是写死的。

## 快速开始

```bash
# 1. 建环境
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 2. 生成示例账单（还没拿到真实账单时用）
.\.venv\Scripts\python.exe tools\make_sample.py

# 3. 自检：解析三份样例，验证去重/退款/转账判定（--seed 顺手把样例灌进账本，方便看界面）
.\.venv\Scripts\python.exe tools\smoke.py

# 4. 启动（Windows 下也可以直接双击 启动.bat）
.\.venv\Scripts\python.exe -m streamlit run app.py
```

浏览器打开 `http://localhost:8501`。

> 第 3 步不加参数时只做自检、不写账本，打开界面会是空的 —— 想看效果就
> `python tools\smoke.py --seed`（写入「演示数据」账本），或者直接把
> `data\wechat\` `data\alipay\` `data\campus\` 里的三份样例拖进「导入」页。

数据全在本机、不上传任何服务器。唯一的对外请求是侧边栏/表格里的渠道图标
（`cdn.simpleicons.org`），断网时图标不显示、其余功能不受影响。

> ⚠️ 用 `python -m streamlit`，不要用 `.venv\Scripts\streamlit.exe`：
> 那个启动器把解释器路径写死在 exe 里，路径含中文时会报
> `Fatal error in launcher`（本项目已换成 `Scripts\streamlit.bat` 转发）。

## 打包成 Windows 桌面版

打包需要额外的依赖（运行本项目用不到）：

```bash
.\.venv\Scripts\python.exe -m pip install -r requirements-build.txt
```

然后双击 `打包exe.bat`，两三分钟后得到：

```
dist\不记账本beta3\不记账本beta3.exe   双击即用（pywebview 套壳，无地址栏）
dist\不记账本beta3.zip                分发用，不含任何账本数据
```

- 版本名在 `打包exe.bat` 第 5 行 `set NAME=` 改
- 桌面版的数据存在 **exe 同级 `data\`**，删掉文件夹 = 数据一起清空
- 首次启动是一本空的「我的账本」，不会带演示数据

## 多用户（账本）

侧边栏可以**新建 / 切换 / 删除用户**，每个用户对应一个独立的 SQLite 文件：

```
data/profiles/
├─ 本人.db        ← 真实账单
└─ 演示数据.db     ← 伪造数据，用于课堂演示
```

- 数据天然隔离，互不可见；换用户会自动清缓存（`@st.cache_data` 的坑）
- 删除用户是真删文件，界面上有勾选确认
- 同名用户不能重复创建；名字里的非法字符会被规范化成下划线

**典型用法**：给老师演示时切到「演示数据」，自己记账时切到「本人」。
两个人（比如你和张熙）也可以各建一个用户做对比。

## 三个渠道怎么拿数据

### 微信
我 → 服务 → 钱包 → 账单 → 右上角「常见问题」→「下载账单」→「用于个人对账」
→ 选时间范围 + 填邮箱 + 验证支付密码 → **24 小时内**收到加密 zip
→ 解压密码在「微信支付」公众号的消息里 → 得到 `.csv`

⚠️ 有 24 小时延迟，要提前申请。

### 支付宝
实测（2026-11）导出的是**「记账本」格式**，和网上教程里的标准流水完全不一样：

```
特别提示：（8 条）
记录时间, 分类, 收支类型, 金额, 备注, 账户, 来源, 标签
```

- **没有交易对方、没有交易单号、没有交易状态**，商户写在备注里 → 适配器用备注回填「交易对方」
- GBK 编码，表头在第 11 行
- 「分类」是你自己填的（餐饮 / 生活日用 / 穿搭美容 / 休闲玩乐 / 借还款 / 投资理财…），
  比关键词规则更准，`classify.py` 里 `CATEGORY_ALIASES` 优先采用它
- 没有单号 → 用「内容指纹 + 同内容第几笔」当主键，**内容完全相同的多笔不会被合并**

老版本「开具交易流水证明」给的是标准明细（`交易时间/交易分类/交易对方/.../交易状态`），
两种格式现在都能吃。

### 校园一卡通
平台：<http://etcard.hzcu.edu.cn:8088/easytong_webapp/index.html#/bill>

实测（2026-11）：**没有导出按钮**；列表页只有日期/消费/金额/时间，**商户名只在详情页**；
后端接口带 `Sign` 签名，程序直接调用会被拒。

所以走「**浏览器内跑一段脚本**」：脚本借用户已登录的页面发请求，签名由页面自己生成。

```
登录一卡通 → F12 Console → 粘贴 tools/campus_grab.js → 自动下载 CSV → 拖进「🎓 校园卡」页
```

脚本已内置在程序里：「🎓 校园卡」页可以一键复制、也能下载成 .js 文件。

**关键发现**：列表接口 `GetDealRec` 的响应里 `businessName` 就是商户名，
前端只是没在列表上渲染 —— 所以不需要逐条点详情。
详见 [tools/一卡通数据获取.md](tools/一卡通数据获取.md)。

⚠️ **最大的坑**：一卡通把「微信/支付宝充值进校园卡」记为 `第三方支付平台转账`，
类型名里**没有「充值」二字**。不处理会被当普通消费，与微信/支付宝的付款**重复计支出**。
抓取脚本已把它映射成「充值」，`dedupe.py` 再判为内部转账剔除。

## 清洗规则（答辩重点）

| 情况 | 不处理会怎样 | 本项目的处理 |
|---|---|---|
| 一卡通充值 | 充值 + 刷卡双重计算 | 标记**内部转账**剔除 |
| 全额退款 | 状态已退款但金额仍为正 | 标记**退款**剔除 |
| 零钱提现 / 余额宝转入转出 | 钱只是换口袋 | 标记**内部转账** |
| 信用卡 / 花呗还款 | 还款不是当期消费 | 标记**还款** |
| 个人转账（红包、AA） | 借出的钱性质不明 | 标记**待确认**，人工核对，不擅自计入 |
| 同一份账单重复导入 | 记录翻倍 | 交易单号作主键，`INSERT OR IGNORE` |
| 理财收益 | 带「余额宝」字样易被误判成转账 | 显式判定为**正常收入** |

## 踩过的坑（真实记录）

1. **`status` 不能参与转账关键词匹配。** 微信红包和转账的状态统一写「已存入零钱」，
   把 status 拼进匹配文本后，「存入」命中转账词，导致真实红包收入（¥288）被误判成内部转账、
   个人转账全部漏判。→ `_text_of()` 现在只拼 对方/商品/分类/备注，status 单独用于退款判定。
2. **关键词别放太宽泛的词。** `转入 / 转出 / 存入 / 取出` 会误伤「转账」「红包」，
   已收敛为 `余额宝 / 自动转入 / 转入到 / 转出到 / 提现 / 零钱通 / 理财通`。
3. **支付宝是 GBK 编码**，`encoding='utf-8-sig'` 直接炸；微信反过来是 UTF-8-BOM。
4. **表头不在第一行**，两家都有 10~20 行说明文字，必须先扫出「首列为『交易时间』」那一行。
5. **金额是字符串** `¥16.00`，还可能带千分位，`float()` 直接炸。
6. **微信新版导出的是 XLSX 不是 CSV**（`微信支付账单流水文件(...).xlsx`），只按 CSV 读会直接失败。
   现在 `normalize.read_bill_bytes()` 用前两字节 `PK` 判断，CSV / XLSX 自动分流，三个渠道共用。
7. **支付宝的文件名里没有「支付宝」三个字**，是 `cashbook_record_20261117_152639.csv`。
   只按关键词识别渠道会认不出来，已补 `cashbook`。
8. **关键词匹配必须忽略大小写**。规则里写 `steam`，账单里是 `Steam`，漏了 20 元；
   现在规则加载时统一转小写，文本也转小写再比。
9. **别把「市民卡」「校园」当校园卡触发词**。杭州市民卡是社保/交通卡，「校园网」「校园超市」是真消费，
   拿它们当充值信号会把正常支出误判成内部转账。现已收敛为
   `校园卡 / 一卡通 / 饭卡 / 城院 / 城市学院`，且必须与 `充值 / 圈存 / 续费` 同现。
10. **「余额宝收益」会被「余额宝」这个关键词吃掉**。收益是真实收入，判定必须**放在理财划转规则之前**，
    否则 2 元收益被当成内部转账，收入直接清零。
11. **支付宝记账本没有交易单号**。只按「时间+金额+对方」做指纹，同一天同一秒的两笔同额消费会被合成一笔。
    现在解析时给内容相同的记录追加序号（`#2`、`#3`），实测 159 条真实记录零丢失，且重复导入仍幂等。

## 可以讲的技术点

1. **适配器模式**：三个渠道三种格式，输出同一个 `Transaction` 数据契约，上层统计逻辑只写一遍
2. **幂等导入**：以交易单号为主键，重复导入不会翻倍
3. **数据契约先行**：金额恒存正数 + 单独的方向列，避免正负号混用
4. **规则可配置**：分类词表放 `data/rules.json`，产品/运营可改而不动代码
5. **可验证**：`tools/smoke.py` 固化了 6 条业务断言，改规则立刻能回归测试
